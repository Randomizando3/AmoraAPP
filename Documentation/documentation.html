Fluxos do sistema (direto: onde editar)

Cada fluxo abaixo descreve “o que mexer” para alterar comportamento/visual/regra.

Fluxo Autenticação e Cadastro

  • Views: WelcomePage, LoginPage, RegisterPage
  • ViewModel: AuthViewModel
  • Services: FirebaseAuthService (login/registro/token), FirebaseDatabaseService (criar/ler perfil), FirebaseStorageService (foto inicial)
  • Models: UserProfile
Para editar o cadastro: UI em RegisterPage + regras/validações em AuthViewModel + persistência em FirebaseAuthService/FirebaseDatabaseService.

Fluxo Discover (swipe, match, boost)

  • Views: DiscoverPage + FiltersPage
  • ViewModel: DiscoverViewModel
  • Services: MatchService (like/dislike/match), FriendService (solicitação), PlanService (permissões/boost), LocationService (distância)
  • Models: UserProfile (plano, boost, preferências/filtros se persistidos)
Boost: duração 3 horas e perfil fica no topo da pilha enquanto ativo. (Regra central fica no PlanService e/ou ranking do MatchService.)

Fluxo Feed (posts, comentários, denúncias)

  • Views: FeedPage, CommentsPage
  • ViewModel: FeedViewModel
  • Services: FirebaseDatabaseService (posts/comentários), FirebaseStorageService (imagem do post), ReportService (denúncia)
  • Models: Post, Comment, ReportItem
Para editar posts: UI no FeedPage + estado/coleções no FeedViewModel + leitura/gravação no FirebaseDatabaseService + formato em Post/Comment.

Fluxo Stories (bolhas + visualização)

  • Views: FeedPage (bolhas), StoryViewerPage (viewer)
  • ViewModel: FeedViewModel (ou lógica local)
  • Services: StoryService (criar/listar/filtrar expirados)
  • Models: StoryItem, StoryBubble
Stories: duração 24 horas. Para mudar regra de expiração/filtragem: StoryService + campos ExpiresAt em StoryItem.

Fluxo Curtidas recebidas (paywall)

  • Views: LikesReceivedPage
  • ViewModel: LikesViewModel
  • Services: MatchService (carregar quem curtiu), PlanService (bloqueio por plano)
  • Models: UserProfile
Para editar paywall: UI no LikesReceivedPage + checagem de plano no PlanService + lista no LikesViewModel.

Fluxo Amigos (lista + solicitações)

  • Views: FriendsPage, FriendRequestsPage
  • ViewModel: (vm dedicado ou lógica local)
  • Services: FriendService (request/accept/deny/list)
  • Models: UserProfile (como alvo/identidade), (estrutura de request no DB)
Para mudar regra de amizade: altere o FriendService (persistência e estados) e reflita na UI dessas páginas.

Fluxo Chat (lista + conversa + presença)

  • Views: ChatListPage / MessagesPage (lista), ChatPage (conversa)
  • ViewModels: MessagesViewModel (lista), ChatViewModel (conversa)
  • Services: ChatService (salas/sumários), MessageService (wrapper), PresenceService (online/last seen), FirebaseStorageService (mídia), FcmTokenService (push)
  • Models: ChatSummary, ChatItem, ChatMessage, ChatBubble
Para editar comportamento do chat: UI no ChatPage + bindings/estado no ChatViewModel + persistência/summary no ChatService.

Fluxo Perfil (dados + fotos)

  • Views: ProfilePage, PhotoGalleryPage, PhotoPreviewPage
  • ViewModel: ProfileViewModel
  • Services: FirebaseDatabaseService (salvar perfil), FirebaseStorageService (fotos/vídeos), PlanService (limites e recursos)
  • Models: UserProfile
Para mexer em fotos: fluxo principal fica em ProfileViewModel + upload em FirebaseStorageService + persistência de URLs em UserProfile.

Fluxo Suporte (ticket)

  • Views: SupportPage
  • ViewModel: (local ou dedicado)
  • Services: FirebaseDatabaseService (salvar ticket), EmailService (opcional: notificar)
  • Models: SupportTicket

Fluxo Verificação (selfie/documento)

  • Views: VerificationPage
  • ViewModel: (dedicado ou ProfileViewModel)
  • Services: FirebaseStorageService (uploads), FirebaseDatabaseService (request), AdminAccessService (validação admin no backoffice)
  • Models: VerificationRequest, UserProfile

Fluxo Upgrade / Planos / Billing

  • Views: UpgradePage
  • ViewModel: (dedicado ou ProfileViewModel)
  • Services: GooglePlayBillingService (compra/assinatura), PlanService (aplicar plano e perks no perfil)
  • Models: UserProfile
Para alterar benefícios do plano: ajuste no PlanService e reflita bloqueios/CTAs no UpgradePage e telas pagas (ex.: LikesReceived).

Fluxo Denúncias / Moderação

  • Views: normalmente acionado a partir do Feed/Perfil/Chat (botões/menus)
  • ViewModel: do contexto (FeedViewModel, ProfileViewModel, ChatViewModel)
  • Services: ReportService (criar report), AdminAccessService (revisão no admin)
  • Models: ReportItem

Fluxo Notificações Push (FCM)

  • Views: (sem view direta; efeito aparece em Chat/Feed/Discover)
  • ViewModels: MessagesViewModel / ChatViewModel (refletir UI)
  • Services: PushNotificationBootstrapper (setup), FcmTokenService (token), ChatService (evento de nova mensagem)
  • Models: (tokens no DB; mensagens via ChatMessage)

Como editar rápido (receita padrão)

Para qualquer funcionalidade nova ou ajuste, o padrão é sempre o mesmo:

1) UI: edite a View (XAML) e o code-behind (.xaml.cs) se tiver handlers. 2) Estado/Regras de tela: edite o ViewModel (Properties, Commands, validações). 3) Regra de negócio / persistência / integrações: edite o Service (Firebase, Billing, etc.). 4) Estrutura de dados: ajuste o Model (campos, defaults, conversões). 5) Se for dado no Firebase: revise paths e consistência (contadores, summaries, timestamps).
